# data.js 갱신 가이드 — 새 사례집(2026년 이후) 반영 절차

감사내비는 `data.js` 한 파일에 모든 점검 사례·근거·문항을 담고, `app.js`(로직)는 이를 그대로
읽어 동작합니다. 따라서 **매년 새 사례집·매뉴얼이 나오면 `data.js`만 갱신**하면 되고,
앱 코드(`app.js`, `index.html`)는 손댈 필요가 없습니다.

이 문서는 충청북도교육청 감사관실 등 운영 담당자가 **매년 반복**할 작업을 정리한 것입니다.

---

## 0. 갱신 전 꼭 기억할 원칙 — 사례 id는 절대 바꾸지 않는다

학교 PC에는 사용자가 체크한 점검 현황(`checks`), 메모(`memos`), 환류 기록(`feedback`),
보관된 회차(`archives`) 등이 모두 **`case.id`(예: `gyomu-03`) 기준**으로 저장돼 있습니다.

- 기존 사례의 내용(`title`/`detail`/`freq`/`checks`/`docs`/`examples` 등)을 새 사례집 기준으로
  **수정**해도 `id`만 그대로 두면 학교의 기존 점검 이력이 유지됩니다.
- 사례가 통합·삭제되면 그 `id`는 `data.js`에서 빼도 됩니다. 학교 localStorage에 남은
  해당 `id`의 체크/메모는 화면에 더 이상 보이지 않을 뿐, 오류를 일으키지 않습니다.
- **신규 사례**는 해당 분야의 다음 번호로 새 `id`를 부여합니다(예: `gyomu-12`가 마지막이면
  새 사례는 `gyomu-13`). 기존 번호를 재사용하거나 번호를 밀어서 다시 매기지 마세요.

> 즉, "기존 id 유지 + 수정은 내용만 + 추가는 다음 번호"가 원칙입니다.

---

## 1. 새 사례집·매뉴얼에서 사례 추출

대상 자료(예: `2026년도 자체감사 사례집`, `2026년도 분야별 감사 착안사항`,
`개정 감사실무매뉴얼`)에서 학교 단위로 적용 가능한 지적사례·점검문항을 골라
다음 항목으로 정리합니다(엑셀 1행 = 1사례):

| 열 | 내용 | 비고 |
|----|------|------|
| 분야 | `CATEGORIES`의 id 또는 한글명 | 예: `bokmu` 또는 `복무·출장` |
| 제목 | 점검 주제 제목 | |
| 내용 | 위반/점검 내용 요약(기관·개인 식별 정보 제거) | |
| 처분 | 처분 문구 | 사례집 방침상 보통 빈 칸 |
| 근거 | 근거 법령·지침 | |
| 점검문항 | 자가점검 문항, **세미콜론(;)으로 구분** | |
| 확인문서 | 확인할 문서, **세미콜론(;)으로 구분** | |
| 빈출 | 빈출 사례 여부 `O`/`X` | `freq>=3` 부여 기준 |
| 확인 | 원문 대조 확인 여부 `O`/`X` | `verified` |

기존 사례와 내용이 같은 경우(연속 지적)는 새로 추가하지 말고, 기존 사례의
`freq`(지적 건수)를 갱신하거나 `examples`에 새 사례 요약을 추가하는 식으로 반영합니다.

## 2. `tools/엑셀변환.html`로 변환

1. 위 표를 엑셀에서 작성한 뒤, 데이터 영역만 복사(머리글 포함해도 자동 스킵됨).
2. `prototype/tools/엑셀변환.html`을 브라우저로 열고 textarea에 붙여넣기 → **변환하기**.
3. 결과로 `const CASES = [ ... ];` 형태의 코드가 생성됩니다.

⚠️ 이 도구는 **신규 사례만 생성**하며, 분야별로 `xxx-01`부터 새로 번호를 매깁니다.
기존 `data.js`에 이미 `gyomu-01`~`gyomu-12`가 있다면, 변환 결과에서 생성된
`gyomu-01`, `gyomu-02`… 는 그대로 쓰지 말고 **`gyomu-13`, `gyomu-14`…** 로
번호를 다시 매겨서 붙여 넣어야 합니다(0번 원칙 참고).

## 3. `data.js`에 반영

1. **신규 사례**: 번호를 재부여한 뒤, 해당 분야의 마지막 사례 다음 줄에 추가합니다.
2. **기존 사례 수정**: `id`는 유지하고 `title`/`detail`/`freq`/`basis`/`checks`/`docs`/
   `examples` 등 내용만 새 사례집 기준으로 업데이트합니다.
3. **분야 추가**: `CATEGORIES` 배열에 `{ id, name, desc }`를 추가합니다(코드 추가 시
   `tools/엑셀변환.html`의 `CATEGORIES` 목록도 같이 맞춰 주세요).
4. **`DATA_META` 갱신** — 가장 중요합니다:

```js
const DATA_META = {
  region: "충청북도교육청",
  target: "학교(초·중·고·유, 사립 포함) 종합감사 대비",
  updated: "2027-03-15",   // 새 사례집을 반영해 data.js를 수정한 날짜로 변경
  status: "2026년도 자체감사 사례집·분야별 감사 착안사항·감사실무매뉴얼 분석 반영"
};
```

- `updated` 값을 바꾸면, 기존에 이 도구를 쓰던 학교 PC에서 다음 접속 시
  **"데이터가 새 기준으로 갱신되었습니다"** 안내 배너가 자동으로 1회 표시됩니다
  (`app.js`의 `checkDataUpdate()`가 localStorage에 저장된 이전 `updated` 값과 비교).
  학교의 기존 점검 체크는 그대로 유지됩니다.
- `status` 값은 화면 하단(`#meta-line`)과 헤더의 데이터 기준 배지(`#data-ver`)에
  그대로 노출되므로, "OOOO년도 ~~ 반영" 형태로 사용자가 한눈에 알 수 있게 작성합니다.

## 4. 검증

```bash
cd prototype
node --check data.js     # 문법 오류 확인
node --check app.js
node tools/build-single.js   # dist/감사내비.html 재생성(배포본)
```

브라우저에서 `index.html`을 열어:

- 헤더에 새 `DATA_META.status`/`updated`가 배지로 표시되는지 확인
- 직전 버전을 쓰던 localStorage가 남아 있는 PC에서 열면 "데이터 갱신" 배너가 1회 뜨는지 확인
- 신규/수정된 분야의 사례 카드, 점검 문항이 정상 표시되는지 확인
- 기존에 체크해 둔 항목(다른 `id`)이 유지되는지 확인

## 5. (선택) 연도별 비교를 더 의미 있게 만들기

[통계·보고서] 탭의 **회차 보관(아카이브)** 기능을 사용하면, 감사 회차마다 준비도·점검
현황·실제 지적사항(`feedback`)을 스냅샷으로 남길 수 있습니다. 매년 데이터를 갱신하기
전에 학교 측에 "이번 회차를 보관"하도록 안내하면, 연도가 바뀌어도 "반복 지적(만성) 항목"
분석이 끊기지 않고 누적됩니다.
